# MF-0068 evidence: seeded learning-path scenarios

Ticket: `.planning/tasks/MF-0068/GOAL.md` (high-risk: seed writes and deletes, re-runnable). Branch MF-0068, issue #103.

## What changed

- `src/dev-seed/plan-path-scenarios.ts` (new): `planPathScenarios`, six path personas, their answers and recorded
  completions, and two path groups. Its own PRNG stream (`seed ^ 0x0068`). It checks every persona's state with
  `pathProgress` and every completion with `isCourseComplete` before it returns.
- `src/dev-seed/plan-seed.ts` (new): `planSeed`, the CLI's one planning call. It runs `planDemoWorlds` unchanged, then
  the first path whose courses are all seeded.
- `src/dev-seed/seed-demo-world.ts`: `seedDemoWorlds` takes an optional `paths` input. Two checks guard it: a pure
  shape check (only path personas on the demo domain, never your account) and a DB check (registry order, packs
  registered, answers are synced questions that are not rejected). Both run before the first delete and again in
  the transaction. The rows are written in the same transaction.
- `scripts/dev-seed.ts`: loads `paths/*.yaml`, prints the personas and the groups. `docs/runbook/dev-seed.md`: a
  table of personas and groups, plus re-run notes.
- `src/dev-seed/types.ts`: path types. `planDemoWorld(s)` is unchanged (`git diff` empty).
