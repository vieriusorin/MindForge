# MF-0051 evidence: check-hooks refuses `pnpm` scripts that do not exist

- New rule, step 3 of `scripts/check-hooks.mjs` (already run by CI, `.github/workflows/ci.yml:50`). The pure core is
  `scripts/lib/pnpm-refs.mjs` (`PNPM_BUILTINS`, `isPnpmRefFile`, `unknownPnpmRefs`).
- It reads `.claude/hooks/**/*.mjs` and `.claude/settings.json` as code. It reads `.claude/{agents,rules,skills}/**/*.md`,
  `CLAUDE.md` and `AGENTS.md` as Markdown, where only code spans and fenced blocks count.
- It fails on each `pnpm <name>` / `pnpm run <name>` where the name is neither a `package.json` script, nor a pnpm
  built-in, nor a `<prefix>:*` family that has a matching script.
- `MF_CHECK_ROOT` points the check at another root. The walk skips symlinks: the tracked `.claude/skills/brag-slim`
  link points into the untracked `.agents/`, so it dangles on Linux CI (review B-1).
- Proof case: the retro Stop hook's `1. pnpm ticket:retro <ID>`. Before the text fixes, `node scripts/check-hooks.mjs`
  exited 1 with 18 hits, the first being `.claude/hooks/lib/retro-trigger.mjs:78 pnpm ticket:retro`.
- First run over the repo found 18 references. None of these scripts was ever in `package.json`:
  - 7 × `ticket:retro`
  - 5 × `ticket:verify`
  - 1 × `ticket:freeze`
  - 1 × `ticket:eval`
  - 2 × `verify`
  - 1 × `db:test:start`
  - 1 × prose (`pnpm for`)
- All 18 were rewritten to name the manual gsd-goal-loop defaults and MF-0080 (#128, reserved: build the `ticket:*`
  CLIs over `scripts/lib`). The rewrites are text only, and every hook still runs to exit 0.
- SC-4, sharing the built-ins with `goal-proofs.mjs`, was withdrawn by the user. MF-0049's proof set is unchanged.
