`MF_AUTHOR_EMAIL=<you> pnpm dev:seed`. The seed approves the diagram the orders are drawn from (it prints

## Notes for the committer

- **Deploy step (every environment, before this ships):** set `ORDER_SHUFFLE_SECRET` (server-only, at least 32
  characters, e.g. `openssl rand -hex 32`; never NEXT_PUBLIC_, never derived from the Supabase keys). Production
  refuses to render a lesson with an order step without it (`src/server/content/order-shuffle-seed.ts`). Local:
  `pnpm dev:setup` writes a random value into `.env.local` once and keeps it; without it, dev falls back to a
  fixed local value. Changing the secret only changes the layout learners first see.

- Re-freezes: MF-0007 SC-1 (`mf-0007-review.db.acceptance.test.ts`, user decision U-a) and MF-0066's own SC-3 /
  SC-8 rows (seeded shown order, standing approval); both recorded in the FROZEN.json histories.
- Rebase onto main: `scripts/check-pack-grounding.mjs` also changed on main (MF-0061 key-rank summary); this
  ticket only adds an import and one block + one summary line before the final summary — keep both.
- The migration is built on MF-0065's 5-arg `record_attempt` (main c7a042b): `create or replace`, MF-0065's body
  verbatim plus the `v_ordered` branch. A later change to the function must carry the branch over.
- `src/features/lesson/**` hunks are separate from MF-0065's QuestionStep / submit-hook hunks.
