## Not verified

- **Hosted environments:** nothing was migrated or synced outside the local stack. Each environment needs the
  migration, then `pnpm db:sync-keys` (runbook B2 → B3). Running expeditions become open there at migration time.
- **Rollout window (review should-fix 4): run B2 and B3 immediately after the merge.** Vercel deploys `main` before the
  migration exists, and until B2 every group page errors (`getGroup` selects `groups.path_slug`). Between B2 and B3,
  choosing **Path** when creating a group is refused (the path registry is empty until the sync).
- **Two members of the browser group were added by SQL** (local fixture) to reach the 4 an expedition needs; their
  join path is covered by SC-3's DB tests, not by a click.
- **Finding from the browser run, resolved by the user (2026-11-06):** an expedition the admin ended by hand, followed
  later by a Move, read "Ended: the group moved to the next course" (`sc-7-last-course-move-disabled.png`), because the
  card derives "moved on" from "its pack ≠ the group's current pack". The user chose neutral wording: the line is now
  "Ended. The group has since moved to the next course." (`movedOnLine`, test red first). The screenshots predate it.
- **Pre-existing, not touched:** the Target number input reports `valuemin/valuemax 0` to assistive tech (it has no
  min/max attributes; MF-0017 form, unchanged apart from its hint text). The MF-0017 concurrent-starts case gave 40P01
  once at freeze; with the new group-row lock it has not recurred.
- **Copy outside the approved batch** (listed in GOAL's Iteration Log, T10): Move dialog body, radio legend, path select
  label, Cancel / Move, `/groups` error text.
- **Review nits left as follow-ups (not fixed here):** (1) if the next course's pack is unregistered, Move stays enabled
  on the Path card and the DB refuses it with the "no next course" message (P0001; the data stays right);
  (2) `groups/[groupId]/page.tsx` throws to the segment's error page if an old course's pack folder is deleted;
  (3) the sync's "no `paths/` folder" case (empties the registry) has no test; (4) `GroupFormFields` restates
  `GroupFormValues`' fields by hand.
