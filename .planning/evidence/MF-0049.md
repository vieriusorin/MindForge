# MF-0049 evidence: `pnpm check:goal-proofs <ID>`

- New check `scripts/check-goal-proofs.mjs`, with the pure core in `scripts/lib/goal-proofs.mjs`. For one ticket it
  fails when:
  - an SC has no `Proof:`;
  - a backticked path (`src/`, `scripts/`, `supabase/`, `packs/`, `e2e/`) in a `Proof:` does not exist;
  - a bare `*.test.ts(x)` in a `Proof:` is not in `git ls-files`;
  - a backticked `pnpm <script>` in a `Proof:` is not a `package.json` script (`exec`, `dlx`, `install` and `vitest`
    are allowed);
  - a FROZEN.json file is named in none of GOAL, LOOP-PLAN or LOOP-VERIFY.
- It fails closed on:
  - a missing GOAL.md;
  - bad FROZEN.json;
  - a duplicate SC;
  - an SC section with no SCs;
  - an SC bullet in another shape (`- **SC-1 Title.**`).
- Its own SC reader keeps wrapped SCs (sub-bullets, blank lines), unlike the shared `successCriteria()`.
- Wiring (user decision C-3): `package.json` `check:goal-proofs`, plus a SKILL.md Stage 4 step to run it before any
  review. It is not a `gate:` script and does not touch `gate:planning` (MF-0060).
- Proof case: today's MF-0024 GOAL with SC-3's path changed back to `mf-0024-sync-prefix.db.acceptance.test.ts`
  (the bad text was never committed, F-1) exits 1 naming SC-3. Today's MF-0024 exits 0.
