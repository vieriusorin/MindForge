# MF-0046 evidence: `pnpm gate:workspace` (pnpm allowBuilds placeholder guard)

- New gate `scripts/check-workspace.mjs`. It fails when `pnpm-workspace.yaml` contains pnpm's placeholder
  `set this to true or false`, or when an `allowBuilds` value is not literally `true` or `false`.
  - Fails closed by an allowlist of line shapes: comments, column-0 bare keys, the `allowBuilds` block, and one level of
    `- item` / `name: value` under other keys. Anything else (anchors, tags, flow maps, explicit or escaped keys,
    merges, duplicate keys, `---`, mixed indent, `true#x`) is a named problem.
  - Uses `node:` modules only.
- CI: a `Workspace check` step before `Install` in `checks`.
- Stop hook: every `gate:*` script runs already, and `isRelevantSource("pnpm-workspace.yaml")` is now true, so an edit
  to that file alone triggers the gates.
- T0 (separate hunk): split the MF-0059 GOAL.md that merge `cc79c34` had concatenated. The retrofit moved to MF-0061
  (issue #96). That turns `gate:planning` green again, along with frozen mf-0028 SC-4 and mf-0053 SC-5, which were
  red on `main` (run 42213004161).
- Review: round 1 changes-requested (3 blocking, fail-open inputs; 1 minor; 2 nits). All fixed with RED-first
  regression tests (`src/test/__tests__/check-workspace.test.ts`, 6/6 red before the fix). Rounds 2 (4 blocking) and 3 (1 blocking class) fixed the same way; round 4 approve.
  SC table and RED lines: `.planning/tasks/MF-0046/LOOP-VERIFY.md`.
