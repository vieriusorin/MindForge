# MF-0048 evidence: plan check refuses role-agent `owns` on NEVER paths

- `validatePlan` (`scripts/lib/ticket-eval.mjs`) reports every role-agent task whose `owns` glob can match a path role
  agents never write. It names the task, the agent, the glob and the NEVER glob it can match.
  - The overlap test `globsOverlap` is exact for ticket-eval's glob semantics. It is a superset of the scope hook's
    stricter `**/` (`util.mjs`), so it never misses an overlap the hook would refuse. At worst it raises a
    fail-closed false positive (`a/**/b` vs `a/xb`).
  - `owns` syntax is an allowlist per segment: `[A-Za-z0-9_.@+-]`, `*`, `?`, whole-segment `**`, and the Next.js route
    shapes `(group)` and `[param]`. Brace sets `{a,b}` (non-nested, at most 64) are expanded and each alternative is
    checked. Anything else is an error, for main-session tasks too. NEVER is compared case-insensitively.
- Main-session tasks (`agent: "inline"` or `"orchestrator"`) are known agents and exempt.
- One owner: `NEVER_GLOBS` is exported from `.claude/hooks/lib/agent-scopes.mjs`, the same list `scopeDecision`
  enforces, and the hook's behaviour is unchanged.
- **Library only (user decision C-1).** Nothing runs `validatePlan` yet: there is no `ticket:eval`. Enforcement before
  BUILD is MF-0060's `gate:planning` wiring, which another contributor owns and can reuse `NEVER_GLOBS` and
  `validatePlan` for.
