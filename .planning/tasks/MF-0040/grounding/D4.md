## D4.S2 Anti-patterns and the alternatives

| Item | Key | Passage | Source |
|---|---|---|---|
| q1 | D | "Consider Skills instead when you want reusable prompts or workflows that run in the main conversation context rather than isolated subagent context." Distractor B: fork "tool calls still stay out of your conversation and only its final result comes back"; C: `/btw` "has no tool access, and the answer isn't added to history." | SA |
| q2 | C | "Use agent teams when teammates need to share findings, challenge each other, and coordinate on their own." / strongest use cases include "Debugging with competing hypotheses". Distractors: table "Teammates message each other directly"; "Agent teams … use significantly more tokens than a single session"; subagents "Best for: Focused tasks where only the result matters". | AT |
| q3 | B | "The subagent doesn't see your conversation history, so the skill's instructions have to stand on their own." / "Despite the name, a skill with `context: fork` doesn't run in a fork of the current conversation … When the task depends on that history, fork the conversation instead of using `context: fork`." Distractor A: "Set `background: false` … to wait for the forked subagent's result"; D: "Claude Code starts a new subagent of the type set in the `agent` field". | SK |
| q4 | A | "Agent teams add coordination overhead and use significantly more tokens than a single session. They work best when teammates can operate independently. For sequential tasks, same-file edits, or work with many dependencies, a single session or subagents are more effective." Distractors: "New modules or features: teammates can each own a separate piece"; "Token costs scale linearly"; "Coordination overhead increases: more teammates means more communication, task coordination, and potential for conflicts". | AT |
| q5 | C | "we recommend finding the simplest solution possible, and only increasing complexity when needed. This might mean not building agentic systems at all. Agentic systems often trade latency and cost for better task performance" / "For many applications, however, optimizing single LLM calls with retrieval and in-context examples is usually enough." Distractors: "add multi-step agentic systems only when simpler solutions fall short"; frameworks "obscure the underlying prompts and responses, making them harder to debug"; "The autonomous nature of agents means higher costs". | BEA |
| q6 | D | "A fork is a subagent that inherits the entire conversation so far … Use a fork when any other subagent would need too much background to be useful, or when you want to try several approaches in parallel from the same starting point." / "Because of that reuse, a fork costs less than a fresh subagent for tasks that need the same context." Distractor C: "it can pass `isolation: \"worktree\"` so the fork's file edits are written to a separate git worktree". | SA |
