## D3.S1 Skills

- **q1** (SK, key B) skill = folder loaded dynamically, repeatable.
  "Skills are folders of instructions, scripts, and resources that Claude loads dynamically to improve performance on specialized tasks. Skills teach Claude how to complete specific tasks in a repeatable way, …"
  Distractors: A = MCP ("MCP connects Claude to external services and data sources."); C = projects ("Projects provide static background knowledge that's always loaded when you start chats within them."); D = custom instructions ("Custom instructions apply broadly to all your conversations. Skills are task-specific and only load when relevant, …").
- **q2** (SK, key D) progressive disclosure.
  "Skills work through progressive disclosure—Claude determines which skills are relevant and loads the information it needs to complete that task, helping to prevent context window overload."
  A: "When you ask Claude to complete a task, it reviews available skills, loads relevant ones, and applies their instructions." / "Claude invokes them automatically when relevant." C: "Skills provide specialized procedures that activate dynamically when needed and work everywhere across Claude."
- **q3** (SK, key A) skills + MCP together.
  "You can use both together: MCP connections give Claude access to tools, while skills teach Claude how to use those tools effectively." Workflow list: "Create tasks in company tools (JIRA, Asana, Linear) following team conventions."
  D: "Skills are task-specific and only load when relevant, making them better for specialized workflows."
- **q4** (AS, key C) trust check before using a third-party skill.
  "Use Skills only from trusted sources: those you created yourself or obtained from Anthropic." "Audit thoroughly: Review all files bundled in the Skill: `SKILL.md`, scripts, images, and other resources. Look for unusual patterns such as unexpected network calls, file access patterns, or operations that don't match the Skill's stated purpose." "Treat like installing software."
  A: "a malicious Skill can direct Claude to call tools or run code in ways that don't match the Skill's stated purpose." D: "Skills that fetch data from external URLs pose particular risk, as fetched content might contain malicious instructions."
- **q5** (AS, key C, expert, platform) API counterpart.
  "Messages API: List `skill_ids` in the `container` parameter and include the code execution tool, whose container the skills run in." "create and upload your own through the Skills API (`/v1/skills` endpoints)."
  A: "Skills uploaded to claude.ai must be separately uploaded to the API."
- **q6** (AS, key A, expert, platform) description drives triggering.
  "The `description` is what Claude matches your request against when determining whether to trigger the Skill, so it must say both what the Skill does and when to use it."
  B: "When instructions mention executable scripts, Claude runs them through bash and receives only the output (the script code itself never enters context)." C: Level 1 "Always (at startup)" = `name` and `description`; Level 2 "When Skill is triggered".
- **card-field-guide** (SK, AS): progressive disclosure levels (AS table); scripts' output enters context (AS); untrusted skills (AS security); "Custom Skills do not sync across surfaces" (AS); projects contrast (SK "Skills vs. projects").
- **diagram-progressive-disclosure** (AS): Level 1 metadata at startup in system prompt; "When you request something that matches a Skill's description, Claude reads `SKILL.md` from the filesystem using bash." Level 3 reference files read when referenced; scripts run via bash, output only; example step "Form filling is not needed, so `FORMS.md` is not read" (the "neither needed" branch).

## D3.S2 Code execution and file creation

- **q1** (FC, key D) "We have given Claude a private computing environment directly in claude.ai. This allows Claude to write and run code (for example Python or Javascript)." "You can also upload CSV, TSV, and other files for data analysis"; creates .xlsx you can download.
  B: "it operates within an isolated, sandboxed container. This means the work happens in a controlled environment separate from your systems." C: Excel (.xlsx) listed; "data visualizations in image files like PNG".
- **q2** (CE, key B) "Claude runs code when the request benefits from computation or file handling: Non-trivial math (large numbers, many steps, precision-sensitive results)". Answers directly: "Simple arithmetic and well-known math facts", "Factual, conversational, or creative requests", "Simple unit conversions or translations".
- **q3** (FC, key A) "Disabling network access prevents data from leaving Claude's sandboxed environment—even if something goes wrong." "Your team still gets Claude's full code execution and file creation capabilities … but with the assurance that nothing can be transmitted outside the sandbox."
  B: "All domains: … it's also the riskiest option." C: "Allow network egress toggled off: Claude operates with pre-installed packages only, with no internet access." D: "If MCP (Model Context Protocol) integrations are enabled, network communication remains possible through those connections regardless of the network egress setting."
- **q4** (FC, key C) "we recommend you monitor Claude while using the feature and stop it if you see it using or accessing data unexpectedly. You can report issues to us using the thumbs down function directly in Claude."
  A: "Implemented sandbox isolation such that no sandbox environments are ever shared between users." B: "Claude can be tricked into sending information from its context (for example, prompts, projects, data via MCP, Google integrations) to malicious third parties." D: All domains "riskiest option".
- **q5** (CE, key B, expert, platform) "When the command completes, the files at the top level of that directory are captured and returned as the `file_id` entries in the result's `content` list. Files written anywhere else stay in the container and aren't returned." "A file Claude wrote elsewhere is still in the container, so you can reuse the container and ask Claude to copy it into `$OUTPUT_DIR`."
  A: "Disk space: The container has 5 GiB of workspace storage." C: web search affects pricing ("Code execution is free when used with web search or web fetch"), not capture. D: "You can reuse an existing container across multiple API requests by providing the container ID from a previous response."
- **q6** (CE, key D, expert, platform) "The container has no internet access, so Claude can't download or install additional packages at runtime: only the pre-installed libraries are available." "Visualization: matplotlib, seaborn".
  A: "Internet access: Completely disabled for security". B: "None of the three tool versions requires an `anthropic-beta` header." C: "`code_execution_20260521` is the same runtime as `code_execution_20260120`. The difference is that the tool description tells Claude about the 90-second wall-clock limit …"
- **card-tape-measure** (FC, CE): private computing environment, file types (FC); "Claude's internet access will vary based on your network egress settings" (FC); no internet in API container (CE); prompt-injection risk + monitor/stop (FC); `$OUTPUT_DIR` capture (CE).
- **diagram-code-execution-request** (CE): "How code execution works" steps 1–7 (evaluate whether code helps; sandbox, no internet; client-tool exception: "the API returns the code execution call without its result. The result arrives in a later response, after you send back the `tool_result` blocks for your client tools."; "Each request runs in a new container unless you pass an earlier response's container ID back"); "When Claude runs code" vs answers directly; `pause_turn`: "You may provide the response back as-is in a subsequent request to let Claude continue its turn … Send the response's container ID back with that request"; output capture + Files API download.

## D3.S3 Memory, project scope and incognito

- **q1** (ME, key D) "Claude saves memory as a set of individual topics as you chat, rather than summarizing conversations after they end. Mention that a deadline moved, and your next conversation already knows."
  B: "Claude saves on its own, and you can also tell Claude to \"remember this\" to save something directly." C: "Some information is never saved to memory, even if you ask. This includes government ID numbers, criminal history, financial account numbers, and immigration status."
- **q2** (IN, key B) "Incognito chats are temporary conversations that aren't saved to your chat history or to Claude's memory." Ghost icon "When starting a new chat with Claude outside of a project".
  A/D: "Claude won't use or add to memory in that chat, and the chat stays in your chat history and Claude can still find it when searching past chats from your other conversations." C: "Incognito mode is currently only available for chats outside of projects, so you won't see the ghost icon when starting a chat within a project."
- **q3** (ME, key C) "Each project has its own memory. While working in a project, Claude uses the project's memory alongside your memory from chats outside of projects, but not memory from other projects." "To keep a project's memory fully separate, turn off \"Use account memory\" under Memory on the project's page."
  B: "Reset memory: Permanently deletes all memories including project memories." D: ghost icon described "When starting a new chat with Claude outside of a project".
- **q4** (ME, key A) "You need to turn memory off before you send the first message. Once the chat starts, the setting can't be changed." "This works the same way in projects. A chat started with memory off in a project doesn't use your memory or the project's memory." "Unlike an incognito chat, the chat stays in your chat history and Claude can still find it when searching past chats from your other conversations."
- **q5** (MT, key A, expert, platform) "The memory tool operates client-side: Claude requests file operations, and your application runs them. You control where and how the data is stored through your own infrastructure." "The `/memories` path is a prefix that your handler maps onto real storage, such as a per-user directory or keys in a database. Memory lives entirely in your application."
  D: "building up knowledge over time without keeping everything in the context window." C contrasts with the server-side code execution container (CE, not cited by this question; the MT page's "client-side" statement makes C wrong).
- **q6** (MT, key C, expert, platform) "A malicious path such as `/memories/../../secrets.env` can reach files outside the `/memories` directory. Your implementation must validate every path in every command to prevent directory traversal attacks." Safeguards: "Resolve paths to their canonical form and verify they remain within the memory directory"; "Reject paths containing sequences such as `../`".
- **card-squirrel-caches** (ME, IN): everyday context remembered (ME "What Claude remembers"); "Each project has its own memory" (ME); incognito vs memory-off (IN FAQ); view/edit/delete topics (ME "View and manage your memory"); Use account memory (ME); never-saved list (ME).
- **diagram-memory-scope** (ME, IN): incognito outside projects, not saved to history or memory (IN); memory off in "+" before first message, stays in history (ME, IN); project memory + account memory, not other projects' (ME); "Use account memory" off (ME).
