## FIX details

### FIX 1 — `platform-foundations.D1.S1.diagram-check-before-trust`, node CHECK

- Wrong text: CHECK label `"Open the cited sources, read the originals, scrutinise the advice"` reached via
  `CUR -no-> TRAIN -> STAKES -yes-> CHECK`. On that path the answer came from training and has no citations, so
  the edge sentence "answer from training → high stakes → open the cited sources" is false.
- Passage: INCORRECT scopes source review to search: "When working with web search results, users should review
  Claude's cited sources." The training-path rule is "Users should not rely on Claude as a singular source of truth
  and should carefully scrutinize any high-stakes advice given by Claude."
- Replacement (page-supported): CHECK label `"Scrutinise the advice; if it cites sources, open them and read the originals"`.
  (Alternative: route TRAIN-high-stakes to WS first; that is a framing choice, so the label change is the minimal fix.)

### FIX 2 — `platform-foundations.D2.S2.q2`, option C (defensible distractor)

- Wrong text: C `"A project, with the template as instructions and the tone uploaded as a knowledge file."`
  Rationale `"…this swaps the two."`
- Problem: PROJECTS does not forbid either placement. It says files go into the knowledge base "which Claude will
  use to better understand the context and background for your individual chats" and that instructions "further
  tailor Claude's responses" (tone is an *example*). A template pasted into instructions plainly works, and a
  tone-guide file in the knowledge base is still read by every chat. C is a less-good layout, not a wrong one, and
  it also meets the stem's goal (stop re-pasting).
- Replacement keeping key B: C `"A project, but with the template and writing rules pasted at the start of each chat in it."`
  Rationale: `"The page says Claude uses the knowledge base for the individual chats within the project and that instructions are defined for each project, so nothing needs pasting again per chat."`
