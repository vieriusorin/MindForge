## D2.S2 The tool-use loop

- **q1** (HT, key C): "Extract the `name`, `id`, and `input` … Run the actual tool … Continue the conversation by sending a new message with the `role` of `user`, and a `content` block containing the `tool_result` type … `tool_use_id`".
- **q2** (OV, key A): "Tools differ primarily by where the code runs. Client tools … run in your application … Server tools (such as `web_search`, `web_fetch`, `code_execution`, and `tool_search`) run on Anthropic's infrastructure." Pricing: "server-side tools can incur additional charges". C rationale reworded from OV: "you see the results directly without handling execution". (verify FIX)
- **q3** (HT, key D): "return the error message in the `content` along with `\"is_error\": true`" + tip "Write instructive error messages. Instead of generic errors such as `\"failed\"`, include what went wrong and what Claude should try next".
- **q4** (HT, key B): "the `tool_result` blocks must come FIRST in the content array. Any text must come AFTER all tool results." Example "this causes a 400 error … ❌ Text before tool_result".
- **q5** (HT, key D): Warning "Treat that content as untrusted … (indirect prompt injection). Keep untrusted content inside `tool_result` blocks rather than `system` prompts or plain user `text` blocks".
- **q6** (HT, key B): "A response can contain both a client `tool_use` block and a `server_tool_use` block that has no result block … Reply with a user message that contains only the `tool_result` blocks for the client tools and keep the same `tools` array; for a server tool Claude called directly, the API runs it on that request and the next response starts with its result block" (qualifier restored, verify NOTE) + formatting note "Text after the results ends the turn early … fails with a 400 error".
- **card** (HT, OV): pairing rule "Tool result blocks must immediately follow their corresponding tool use blocks"; `is_error`; untrusted tool content; server tools "you do not need to handle `is_error` results"; Tool Runner automates the loop. Cleaner-wrasse analogy is the analogy, not a sourced claim.
- **diagram** (HT, OV): the loop of `stop_reason: tool_use` → run → `tool_result` / `is_error` → next request. The "no" branch no longer names `end_turn` (not on either page); DONE is qualified because OV links "Stop reasons and fallback" for non-final stops. (verify FIX)
