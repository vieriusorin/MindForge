### Checked and found sound
- Migration (`supabase/migrations/20261106100000_mf0054_group_pins.sql`): `private.group_pins` has RLS on, `revoke all` from public/anon/authenticated, and no policies or grants. Every function is `set search_path = ''` with fully qualified names. `pin_group_for` is revoked from public, anon and authenticated, so only the owner (postgres) and the definer `private.pin_group` can call it. `private.pin_group` takes the uid from `auth.uid()` and raises 42501 when it is null. `unpin_group` and `list_my_pins` filter on `auth.uid()`. A co-member has no read path to another learner's pins, and the only cross-user output (`evicted_name`) is the caller's own group. Membership is checked under the advisory lock and backed by the composite FK with cascade. The cap check runs after the lock, and each statement in a volatile plpgsql function takes a fresh READ COMMITTED snapshot, so the second caller sees the first one's COMMIT. Eviction uses `order by pinned_at, group_id` ascending, `list_my_pins` uses `desc, desc`, and `order-pinned-groups.ts:16-21` sorts desc on (pinnedAt, groupId), so the key is the same up to precision (see the note below).

Your joins are pinned in ascending `joinedAt` order through `private.pin_group_for`, so ccdv-f ends up as the newest pin. ### Notes
- [note] src/server/groups/order-pinned-groups.ts:17 — `Date.parse` cuts `pinned_at` to milliseconds, but the DB orders and evicts at microsecond precision (`list_my_pins`, the eviction subquery). Take two pins less than 1 ms apart, where the earlier pin has the greater `group_id`. The DB calls the later one newest, but TS treats them as a tie and picks the earlier one by `group_id`. The sidebar's first row and the primary pack would then disagree with the DB's own order. The seed works around this with `pg_sleep(0.002)` (`seed-demo-world.ts:482`), so the gap is known. For a real user it takes two pins inside 1 ms, which the advisory lock and the round-trips make practically unreachable. To close it, `list_my_pins` could return a rank or the full-precision value as text.
- [note] src/features/groups/components/pin-toggle/pin-toggle.tsx:23-29 — the status and error text render inside the toggle's wrapper, between the row card and the button (`group-list.tsx:28`, `flex items-center`). Nothing constrains their width, so on a narrow viewport `Unpinned "<long name>" to make room.` squeezes the `min-w-0 flex-1` card link. This is layout only and does not affect correctness. Check it in the browser at mobile width.
- [note] src/features/groups/actions.ts:139 — `unpinGroup` maps errors with `pinRpcError`, so a 42501 on unpin would read "You can only pin groups you belong to." `private.unpin_group` never raises 42501 itself (it only filters on `auth.uid()`), so the only way to get there is a grant-level permission error. The message is wrong but not reachable in normal use.
